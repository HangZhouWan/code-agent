# 通用 AI Agent 需求设计文档

**日期**：2026-07-02
**定位**：学习驱动的通用 AI Agent 平台，对标 OpenClaw
**学习周期**：1-2 个月

---

## 一、项目目标

构建一个通用 AI Agent 平台，用户可以自然语言下达指令，Agent 自主完成理解意图→规划→调用工具执行→反馈结果的闭环。项目以学习为核心目的，重点关注 **运行时基础设施（Harness Engineering）**：权限沙箱、Hooks 机制、上下文管理。

---

## 二、整体架构

```
┌─────────────────────────────────────────┐
│            Web Chat UI (前端)             │
├─────────────────────────────────────────┤
│            API Gateway (ws/http)         │
├─────────────────────────────────────────┤
│  ┌─────────────────────────────────┐    │
│  │       主 Agent (Orchestrator)    │    │
│  │  - 理解用户意图                   │    │
│  │  - 拆解任务                      │    │
│  │  - 派发子 Agent                  │    │
│  │  - 汇总结果                      │    │
│  └──────────┬──────────────────────┘    │
│             │ dispatch                   │
│  ┌──────────▼──────────────────────┐    │
│  │       子 Agent (Worker)          │    │
│  │  - 独立上下文                    │    │
│  │  - 独立工具权限                  │    │
│  │  - 执行后归还结果                │    │
│  └─────────────────────────────────┘    │
├─────────────────────────────────────────┤
│          Agent Runtime (Harness)         │
│  ┌──────────┐ ┌────────┐ ┌───────────┐  │
│  │ 权限沙箱  │ │ Hooks  │ │ 上下文管理 │  │
│  └──────────┘ └────────┘ └───────────┘  │
├─────────────────────────────────────────┤
│              工具层 (Tools)              │
│  File │ Shell │ Code Search │ Git │ Web │
├─────────────────────────────────────────┤
│          LLM 抽象层 (Model Adapter)       │
│    OpenAI  │  Anthropic  │  Others...    │
└─────────────────────────────────────────┘
```

### 架构约束

- Harness 是所有 Agent 的唯一执行通道，Agent 不能绕过它直接调工具或 LLM
- 主 Agent 和子 Agent 共享同一套 Runtime，但拥有独立的上下文和受限的工具权限
- LLM 抽象层向上层屏蔽模型 API 差异

## 三、LLM 抽象层

### 目标

屏蔽不同模型 API 的差异，向上层提供统一的调用接口。

### 功能需求

- **统一接口**：`chat(messages, tools?, options?)` → 标准化响应 `{role, content, tool_calls?}`
- **适配器模式**：每个厂商一个 adapter，各自处理消息格式、tool calling schema、流式输出差异
- **协议检测**：支持自动识别 API endpoint 的协议类型，也支持手动指定
- **多厂商支持**：OpenAI 协议、Anthropic 协议、其他兼容 OpenAI 协议的服务
- **关键能力**：
  - 非流式与流式输出统一
  - Tool calling 格式转换（OpenAI function calling ↔ Anthropic tool use）
  - 错误重试与 fallback

### 范围外

- 不做多模型负载均衡/路由
- 不做复杂的 token 计费统计
- 不做请求队列/并发限流

## 四、Agent Runtime（Harness 层）

### 4.1 权限沙箱

- **能力声明**：每个 Agent（主/子）启动时声明所需的工具权限，格式如：
  ```
  {
    tools: ["file.read", "shell.exec"],
    paths: ["/workspace"]
  }
  ```
- **执行前拦截**：Runtime 在每次工具调用前校验权限——此 Agent 有权调用此工具？参数是否在允许范围内？
- **危险操作分级**：
  - **安全级**（直接放行）：读文件、搜索代码、HTTP 只读请求
  - **需确认级**（通知用户审批）：写文件、执行 Shell 命令、git commit
  - **高危级**（默认拒绝）：`rm -rf`、`sudo`、访问系统敏感路径、git push --force
- **沙箱隔离**：子 Agent 的文件读写和 Shell 执行限制在指定工作目录内

### 4.2 Hooks 引擎

- **Hook 挂载点**：
  - `on:agent:start` / `on:agent:end`
  - `on:tool:before` / `on:tool:after`
  - `on:agent:error`
  - `on:message:send` / `on:message:receive`
- **Hook 能力**：在工具调用前修改参数、在工具调用后处理结果、在发生错误时触发通知等
- **用途示例**：工具调用日志记录、敏感信息过滤、自动 code review

### 4.3 上下文管理

- **会话管理**：每个用户会话维护独立的消息历史
- **上下文窗口**：跟踪 token 用量，接近模型上限时触发压缩（摘要历史消息、裁剪旧内容）
- **子 Agent 隔离**：子 Agent 从主 Agent 继承必要的上下文摘要，但不继承完整对话历史
- **工具结果回注**：子 Agent 的工具调用结果自动注入对应上下文

## 五、Agent 编排层

### 5.1 主 Agent（Orchestrator）

- **职责**：理解用户意图 → 制定执行计划 → 拆解为子任务 → 派发子 Agent → 收集结果 → 回复用户
- **生命周期**：
  1. 接收用户消息
  2. 分析任务，生成结构化执行计划（子任务列表）
  3. 对每个子任务，创建子 Agent 并派发
  4. 等待子 Agent 返回结果
  5. 根据需要追加子任务或追问用户
  6. 汇总所有结果，生成最终回复
- **子任务调度**：
  - 并行派发：相互独立、无数据依赖的子任务同时执行
  - 串行派发：B 依赖 A 的输出结果，按序执行

### 5.2 子 Agent（Worker）

- **本质**：独立 LLM 循环（思考→调用工具→观察结果→继续思考），拥有独立上下文和受限工具权限
- **输入**：主 Agent 给出的具体任务描述 + 必要上下文
- **输出**：任务执行结果
- **约束**：
  - 不直接和用户交互
  - 工具权限由 Runtime 动态分配（比主 Agent 更窄）
  - 有执行超时和最大推理轮次限制

### 5.3 派发协议

主 Agent 通过结构化方式创建子 Agent：
```
dispatch_subagent({
  task: "具体任务描述",
  tools: ["file.read", "code_search"],
  context: "辅助上下文"
})
```

## 六、工具层

### 6.1 工具注册与调度

- **工具接口**：`name`、`description`（供 LLM 理解用途）、`parameters`（JSON Schema）、`execute(args)`
- **工具注册表**：全局注册中心，按名称索引
- **调用流程**：LLM 返回 tool_calls → Runtime 校验权限 → Hooks（before）→ 执行 → Hooks（after）→ 结果回注上下文
- **扩展方式**：新增工具只需实现工具接口 + 注册到工具表 + 在权限系统中声明

### 6.2 首期工具

| 工具 | 能力 | 权限分级 |
|---|---|---|
| File | 读/写/列表/搜索文件，限定 workspace | 读安全，写需确认 |
| Shell | 执行 shell 命令，支持命令白/黑名单 | 需确认，高危拒绝 |
| Code Search | 基于 grep/find 的文本搜索 | 安全 |
| Git | status/diff/log/branch/commit | 读安全，变更需确认 |
| Web | HTTP 请求 + 网页内容提取 | 安全（只读） |

## 七、API Gateway

- **通信方式**：WebSocket 为主（流式推送 Agent 执行过程），HTTP 为辅（会话管理、历史查询）
- **核心端点**：
  - `POST /sessions` — 创建会话
  - `WS  /sessions/:id/chat` — 消息交互（用户发送 + Agent 流式回复）
  - `GET  /sessions/:id/history` — 历史消息
  - `POST /tools/:call_id/approve` — 危险操作审批回调

---

## 八、Web 聊天界面

- 对话式 UI：左侧会话列表，右侧聊天区
- 实时流式显示 Agent 回复内容
- 工具调用过程可视化（当前执行状态展示）
- 审批卡片：危险操作弹出确认/拒绝按钮
- 交互组件：消息输入框、发送按钮、会话切换

---

## 九、错误处理策略

- **LLM 调用失败**：自动重试（最多 3 次，指数退避），重试耗尽后向用户报告
- **工具执行失败**：错误信息返回给 Agent，Agent 自行决策重试/换方案/向用户求助
- **子 Agent 超时**：主 Agent 收到超时通知，决定重试、跳过、或由其他子 Agent 补充
- **不可恢复错误**：API key 无效等配置错误，直接终止并向用户明确说明原因
